# Memberships and API keys

- **A membership gives a user a role** on a tenant (`admin`, `operator`, `user`, `viewer`). Memberships are objects of the tenant's namespace, read and written only by the admins of the tenant (the relations `can_read_memberships` and `can_write_memberships`) or a platform administrator. A membership cannot be edited, because a role is an OpenFGA tuple that cannot be changed in place: to change a role, delete the membership, and create another. There is one per user and tenant: its name is derived from the email, so a second one is a `409`. The owner of a tenant already is admin through the tenant and a membership for it is refused (`409`, `owner_is_admin`): to hand a tenant over, give someone else the `admin` role. Only users are supported, a group is refused (nothing writes the tuples a group needs).
- **Deleting a membership is not an instant revocation**: the object goes at once, its tuples within about a minute (measured on the cluster in the test below).
- **An API key is a service account of Authentik** (`apikey-<id>`), made by Crossplane when the key is created. It belongs to the user who created it, not to a tenant. Its rights are only OpenFGA tuples: the scopes `tenants:read`, `instances:read|write`, `images:read|write`, `memberships:read|write` on each tenant of its `grants`. `POST /v1/apikeys` waits for Crossplane to make the account, then answers with the key **once** (read from a Secret that is deleted as it is read) and the `identity` to exchange it with at Authentik (`client_credentials`) for an access token. If the account cannot be made in time, the key is removed and the answer is `503`.
- **Only a person manages keys**, signed in with Authentik: a key cannot create, read, or delete keys. `API_KEY_CREATION` says who creates them (the platform administrators, or any person); anyone lists, renames and revokes their own (a key can always be revoked). Someone else's key answers `404`.
- **A key never exceeds its creator**: the API checks at creation that the creator holds each scope on each tenant, and a tenant that does not exist is refused like one the creator cannot see (`403`). A key is never a platform administrator: it cannot create a tenant, nor choose a plan. `tenants:write` renames the tenant it is given on and deletes it (which destroys its virtual machines), and only a creator who administers that tenant can give it. `GET /v1/apikeys/scopes` lists the scopes, `<resource>:<verb>`, with what each does.
- **A key always expires**: `expiresAt` is required, in the future, within `API_KEY_MAX_LIFETIME` when it is set, and fixed. OpenFGA refuses the key from that date, to the second, because its tuples carry the condition `not_expired` and the API sends the current time with every question. The list shows `expired` as soon as the date has passed. The account in Authentik does not expire: deleting the key removes its token and its tuples.
- **What a key may do and until when cannot change**, only its name: to change them, delete it, then create another. A key cannot be rotated either.
